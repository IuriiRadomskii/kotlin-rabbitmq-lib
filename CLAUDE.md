# Инструкции для AI Assistant

## О проекте
Это Kotlin-библиотека для работы с RabbitMQ. Основная цель - предоставить удобный,
потокобезопасный и производительный клиент который может быть использован как в Kotlin так и Java

## Ключевые принципы
1. **Потокобезопасность** - все публичные API должны быть thread-safe
2. **Управление ресурсами** - соединения и каналы должны корректно закрываться
3. **Производительность** - используем пулы для переиспользования ресурсов
4. **Kotlin-first** - предпочитаем идиоматичный Kotlin код (корутины, extension functions)

## Стандарты кодирования
- Не использовать корутины 
- Все публичные API должны иметь KDoc комментарии
- Тесты пишем на JUnit 5
- Интеграционные тесты пишем с применением testcontainers

# Ресурсы
## Channels
Доступ к каналам должен быть через try-with-resources модель.
Т.е. публикация сообщение на канал
Задачу на публикацию передавать как lambda функцию после публикации канал закрывается
Если добавлен ReturnListener, то ожидатьт ответа от RabbitMQ и потом закрывать канал. Ждать не более чем заданный тайм-аут.
Каналы создаются через ресурс Connections

## Connections
Можно создавать множество каналов в рамках одного Connection
Класс управляющий Connection должен уметь делать recover на случай обрыва сети или рестарта RabbitMQ.
Учитывается встроенная возможность amqp-rabbit по восстановлению каналов.

## Publishers
Главным параметром Publisher является класс который может принимать задания на публикацию (см. Channels)
Publisher методы отправки должны принимать exchange и routing key, т.е. получатель определяется через метод отправки
При недоступности/ошибке channel or connection должно выбрасываться кастомное исключение с информацией
Вызов метода паблишера синхронный и выполняется в клиентском потоке

## Consumers
Архитектура Consumer включает в себя внутренние воркер консьюмеры, которые работают с одним и только одним каналом в одном потоке. Весь жизненный цикл такого консьюмера завязан на работу в одном потоке.
Внутренние консьюмер-воркеры управляются контейнром, который может запускать/останавливать/пересоздавать после ошибки внутренние консьюмер-воркеры
Consumer параметризуется MessageHandler, который принимает враппер дто в котором лежит сообщение из RabbitMQ
Consumer параметризуется очередями которые слушаются при запуске
Consumer параметризуется размером пула воркеров
Сообщения буферизируются через очереди из пакета java.util.concurrent.
Consumer имеет свой жизненный цикл: создание и проверка параметров, запуск, остановка с ожиданием завершения работы MessageHandler, очистка и закрытие ресурсов
Воркер потоки платформенные
Демоны супервайзеры могут быть построены на virtual threads

## Serialization
- при конфигурации паблишера можно задать способ сериализации (т.е. сам RabbitPublisher может быть параметризирован)
- при конфигурации консюмера можно задать способ десуриализации (т.е. MessageHandler может быть параметризирован)

## Ресурсы каналов, соединений и консьюмер имеют следующий жизненный цикл
- создание
- инициализация
- остановка с ожиданием завершения текущих задач
- закрытие сетевых ресурсов и ресурсов JVM
